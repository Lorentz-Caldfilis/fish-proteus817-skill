# Agent instructions for DeepSeek Harness desktop setup

When a user asks you to install this repository's Proteus skill in DeepSeek Harness desktop, use this workflow. Reading the repository or requesting a circuit alone is not permission to install. Obtain the user's authorization before changing their desktop profile or installing dependencies. A request to install grants that authorization; do not ask again when it already covers these steps. If permission or a shell/filesystem capability is unavailable, explain the blocker and give the commands below; do not claim installation succeeded.

This copy documents the optional `codex/school-non-system-paths` branch. Ordinary installations should use `main` and its own instructions: main prioritizes the skill's core circuit workflow and does not require this school-specific writable-path policy. Apply steps 2–5 below only after selecting the school branch for a user who needs it.

1. For ordinary use, clone `main` into an unused persistent local directory and follow that checkout's instructions. When the user needs no system-drive writes, use `git clone --branch codex/school-non-system-paths https://github.com/Lorentz-Caldfilis/fish-proteus817-skill.git`. An old or slow computer alone does not require this branch. Use the historical `demo/portable-lab` branch only if that demo is explicitly requested; do not assume it includes this policy. Inspect an existing checkout's branch and local changes before reusing it; preserve user changes. Work on the same Windows machine as the user's existing DeepSeek Harness and licensed Proteus 8.17 SP2. Keep this repository in a persistent location: the installed tool uses its paths. Open Harness once to create its profile. Never ask for or handle account credentials.
2. Before starting Harness, follow `docs/configuration.md` school-machine policy: use non-system-drive repository/venv and actual initialized Harness home; set TEMP/TMP, `FISH_PROTEUS_TEMP_DIR`, and pip cache policy in that launch environment. Keep strict Windows mode enabled for school computers. Never migrate a home or fall back to HOME/system TEMP. External application writes remain outside this skill's complete control. From the repository root, use Python 3.10 or newer and a repository-local virtual environment. In PowerShell:

   ```powershell
   if (-not (Test-Path .venv)) { py -3 -B -m venv .venv }
   .\.venv\Scripts\python.exe -B -m pip install --no-cache-dir -e ".[dsh]"
   .\.venv\Scripts\python.exe -B tools/dsh_install_desktop.py --dsh-home $ActualInitializedHarnessHome --dry-run
   ```

   If `.venv` already exists, reuse it only if it is this repository's intended environment and is usable; do not delete or replace an existing environment. Dependency installation needs network access or locally available packages. Read the dry-run JSON, especially `status`, `errors`, and `warnings`.

   Run these commands one at a time and check each exit code; stop on failure rather than continuing into the installer. If `py` is unavailable, use a verified Python 3.10+ interpreter.

3. Resolve missing prerequisites using the reported diagnostics. `--dsh-executable` selects the installed desktop executable; `--dsh-home` selects a home only when it is actually the home used by Harness. `FISH_PROTEUS_EXE` selects an installed `PDS.EXE`; other paths are documented in `docs/configuration.md`. Set any overrides in the same shell invocation as the installer. The installer saves the verified executable, library, sample and template paths in its desktop configuration, so the running Harness does not need to inherit that temporary shell environment. Do not invent paths, change unrelated profile settings, download Proteus, or bypass version checks. If a required path or authorization is unavailable, stop and report it.
4. Once dry-run reports `ready` and the user has authorized installation, run the same installer without `--dry-run`, keeping any verified path options. It installs the skill and registers the companion desktop tool together, with backups. Do not use `dsh_install_skill.py` as a substitute for desktop tool registration. If it reports an existing project-level skill that shadows the global one, inspect the reported warning and update it only with the user's authorization and the documented backup-preserving `--update` command.
5. Read the actual result. Report installation only for `installed`, `updated`, or `unchanged`, then check whether `fish_proteus_design` appears in the desktop session and call `capabilities` if available. The installer requests hot reload; if the tool is not available yet, say it is unverified and follow the host's reload instructions. Do not claim a native simulation or a successful model/tool call unless it actually ran. `--uninstall` is available for the managed installation.

For ordinary circuit tasks after installation, follow `skills/fish-proteus817/SKILL.md`. If this agent cannot execute local commands or access the desktop profile, the user must provide an environment with those capabilities.
