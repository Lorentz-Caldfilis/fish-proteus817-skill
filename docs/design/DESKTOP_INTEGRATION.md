# DSH 桌面接入与通用任务设计

设计日期：2026-10-29。用户已授权文档先行后的自主实现；本文先登记目标和验收，后续状态以实际报告为准。

## 用户目标

一次安装后，用户在现有 DSH 桌面会话描述设计目标或提供本机文件，即可使用本机 Proteus。用户不逐次运行启动器、选择操作白名单、创建任务目录或登记内部 ID。课程案例是可选参考和回归用例。

## 当前问题及保留基础

专用 headless 启动器注入的工具不出现在普通桌面 profile。其固定任务根、预登记输入和全局工具 guard 适用于独立受限验收，不适合作为桌面插件。保留通用 Library/Circuit/Session、原子 edit、revision、完整原生证据及验证后端；新建薄的桌面接入和会话任务层，避免重写已验证的原生适配。

## 一次性安装

安装器核验 Python、所需依赖、本机 DSH 布局与 Proteus 资源；安装配套 Skill，并仅向选定桌面 profile 增加本插件配置。保留原文件备份、安装清单和撤销入口；重复安装幂等，升级可审查。普通使用不依赖 PowerShell 临时环境变量。优先使用 DSH 官方本地插件/配置热加载机制，不修改 app.asar、不覆盖 DSH 自带模块，不改变其他插件、模型、账号或用户工程。

本机 loader 查证补充：同一 entry ID 的 name 改变不会重新 import 原入口，配置更新只重新调用旧 callback；删除旧 ID 与添加新 ID 的处理又存在并行卸载窗口。因此采用固定极薄 bootstrap v1，配置变化时动态 import 内容地址实现模块。安装器保留双 JS 模块的逐字节缓存并以 sourceIdentity 变更触发配置更新；普通升级不依赖清理 ESM 缓存，也不同时注册两个同名工具。

## 桌面工具与任务层

- 工具由持久插件注册；不安装全局 guard，不禁用桌面其他工具，不替换模型或工具模式。
- 按真实 DSH 会话隔离任务，自动生成任务目录与资源清单；同一会话可以显式创建/切换多个任务，重启可恢复已有任务。
- 自动发现 Proteus 安装、器件库、样例和格式容器。用户提供的工程/固件路径由资源接口登记为只读输入，后续内部使用 ID；不要求启动时预先列齐资源。
- 用统一通用设计工具操作当前任务。适配层可自动填充当前 revision，但明确给定的旧 revision 仍须拒绝；失败保持原子性。任务与资源管理不隐含新建/清空电路。
- 原始输入不被覆盖。新建和编辑结果保存在任务副本，可导出至用户明确选择的新目标；当前导出携带已登记/提取到任务 inputs/firmware 的固件，既有工程旁的其他外部文件须另行解析和确认，不能泛称任意工程完整依赖打包。不同会话/任务不能串用状态；原生仿真串行访问。
- Skill 根据目标选择器件、模板、固件和验证方法，调用按需帮助，解释真实阻塞。模型能力不等于具体器件/格式/版本的兼容保证；不承诺所有 Proteus 功能。

## 实施顺序

1. 查证官方与本机版本的工具执行上下文、工作目录、配置插入和热加载接口。
2. 实现可复用的会话/任务/资源层和桌面插件；复用既有设计与原生接口。
3. 实现一次性安装、幂等更新、备份/撤销和安装诊断；更新 Skill、双语使用说明与公开文件清单。
4. 离线验证会话隔离、任务恢复、资源登记、冲突和取消行为；在正常桌面 profile 做实际工具加载与调用验收。
5. 用自然语言完成独立设计任务及有针对性的原生验证，保留实际调用和结果，不复用历史结论冒充本轮成功。
